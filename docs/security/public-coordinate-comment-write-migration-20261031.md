# いふう・くじら公開API：座標・コメントの安全な書込移行（設計用・未実装）

作成日: 2026-10-31
対象: `kunihiro1200/property-search-app`、公開サイト `property-site-frontend`

> **この文書は設計レビュー用です。アプリケーションコード、GAS、GitHub定期実行、Vercelの本番設定、DB、認証キーを変更しません。**
> 導入はそれぞれ別PRで、実際の呼出元と本番互換性・データ更新の検証後に行います。

## 現状・実際の呼出元

| API | 匿名で到達 | 書込先／動作 | 公開画面からの利用 |
|---|---|---|---|
| `POST /api/public/properties/:propertyNumber/save-coordinates` | はい | リクエストのlatitude/longitudeを`property_listings`へ直接書く | `PublicPropertyDetailPage.tsx` と `KujiraPropertyDetailPage.tsx`。DB座標がない場合、Google Map URLからブラウザで抽出し保存 |
| `POST /api/public/properties/:id/sync-comments` | はい | Athomeシートを読み、`PropertyDetailsService`等を介してコメントを同期 | 両詳細ページの`/complete`が`needsSync`を返す場合に自動POST |
| `POST /api/public/properties/:identifier/refresh-essential` | はい（現本番） | 画像・基本情報の更新 | 管理者モードの更新ボタン |
| `POST /api/public/properties/:identifier/refresh-all` | はい（現本番） | 全データの更新 | 管理者モードの更新ボタン |

後者2本は別のDraft PR #21で既存`requireStaffOrMachine`を追加済み（**未マージ・本番未反映**）。本設計PRでは触れない。

### 単純に匿名POSTを禁止できない理由

- `frontend/src/components/PropertyMapView.tsx` は**DBに既に座標のある物件だけ**地図一覧のピンに含める。公開詳細ページからの座標保存を先に停止すると、新規物件の地図一覧への反映が欠落する恐れがある。
- `GET /api/public/properties/:id/complete` はコメントが空なら`needsSync`を返し、公開ページが匿名`sync-comments`をPOSTする。この処理を先に止めると、新規・欠損物件のコメントやパノラマ表示の回復が途切れる恐れがある。
- 表示用GET、物件検索、地図、問い合わせは一般のお客様に対してログイン不要のまま維持する。

## 優先A: 不正な座標書込をなくす

**信頼の境界:** ブラウザから渡された緯度経度は信用しない。公開APIにサービスロールDB書込を任せない。

推奨の移行手順：

1. 物件のDBに記録されたGoogle Map URLを**サーバー側の信頼できる情報源**として使い、管理された同期ジョブで緯度経度を取得する。公開ブラウザ送信値を正としない。
2. `google_map_url`はHTTP(S)の承認済みGoogle Mapsホストに限定し、短縮URLを解決する場合も許可ホスト・リダイレクト・タイムアウト・回数制限を実施する（SSRF、過剰な外部通信を防ぐ）。
3. 不正な数値・範囲外・無効URLのときはDBを更新しない。座標の`0`や`null`も明示的に扱い、NaN/Infinityを拒否。
4. 既存全物件の座標件数、地図に表示できる件数を確認し、**新しい管理ジョブによる未取得座標の補完**が正常に動くことを確認する。
5. その後、現在の匿名`save-coordinates`を社員認証＋機械認証が必要な管理用経路へ変更、または廃止。公開詳細ページでは座標の閲覧・ブラウザ内でのマーカー表示は維持するが、匿名POSTでDBへ書き込ませない。
6. 地図一覧のピン数、新規物件の掲載反映、いふう／くじら両サイトの地図表示を変更前後で比較する。

**Do not:** 匿名POSTに単純にJWTを付けるため、公開ブラウザへ`CRON_SECRET`等のサーバー秘密値を配布しない。

## 優先B: 公開コメント同期を制御されたジョブに移す

1. 公開`GET /complete`は物件詳細・既存コメントを返す**読取専用**経路にする。内部メモの非公開ルールと`propertyAbout:null`は維持する。
2. 欠損コメントの同期は認証済みスタッフ操作、または安全な内部スケジュール／キューから実行。**匿名閲覧1回ごとにGoogle Sheetsを読みDBを書き換えない**。
3. 同一物件の重複ジョブを抑止（DBベースの排他／キューの一意キー）、再実行までのクールダウン、実行上限・タイムアウト・監査ログを設ける。
4. 初回掲載時や`needsSync`相当の欠損を検出したときに、認証済みジョブで補完する。公開ページは保存済み情報を表示し、欠損時の表示を壊さない。
5. 両公開詳細ページから匿名`sync-comments` POSTを除去するのは、管理ジョブからの補完成功、Google SheetsとDBの件数・更新結果、コメント・パノラマの回帰試験が済んだ**あと**。
6. 移行後は`sync-comments`を`requireStaffOrMachine`等で保護（同等以上の認証）し、匿名POSTは401。社員向け手動同期は維持する。

### 実測上の注意
Vercel runtime logの`requestPath`集計は**ログ行数**であってリクエスト件数ではない。利用頻度や攻撃の有無はこの数字だけで断定しない。

## 試験ゲート（本番マージ前）

- 無認証で上記書込APIを呼び出してもDB書込・Sheetsアクセス・内部処理が発生しない。認証拒否401をユニット／隔離HTTPテストで確認（テストデータのみ）。
- 有効な社員セッション／機械認証の正常系は**隔離テスト環境**でのみ実行。動作確認のために本番データに書き込まない。
- 公開物件一覧、地図一覧、詳細、画像、問い合わせが匿名で表示可能。
- 新規物件の地図ピン・コメント補完が、閲覧者のアクセスなしでも所定の時間内に更新される。
- コメント内部メモ・非公開物件の公開漏えいがない。
- 新旧データ件数・実行所要時間・失敗数・Google API利用量を比較する。
- 既存GAS、GitHub Scheduled Property Sync、Vercel productionの相互干渉・二重同期がない。
- 段階的導入中のロールバックとデータ整合性の手順を用意する。
